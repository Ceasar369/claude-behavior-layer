# 2026-07-27

Seed entry. One day file, showing what a closed session leaves behind.

Reworked how the token refresh decides when to fire. It used to wait for a
rejected request and then retry, which meant every expiry cost one user-visible
stall. It now refreshes ahead of expiry instead. That trades a clock we do not
fully control for a stall we were causing on purpose, and the clock is the
cheaper problem.

Considered refreshing on a timer and dropped it. A timer keeps firing for a
session nobody is using, and the load it adds scales with idle users rather than
active ones.

Left open: what happens when the refresh itself is rejected. Today it surfaces as
an ordinary sign-out, which is honest but abrupt. Nobody has designed the gentler
version, so nobody built it.
