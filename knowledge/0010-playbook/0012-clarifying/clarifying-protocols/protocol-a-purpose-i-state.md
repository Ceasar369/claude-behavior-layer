# Protocol — A Purpose I State

Up: [[clarifying-protocols-MOC|Protocols]]

When the exchange turns a purpose I state into a design.

## The parts it touches

My words, where I stated the purpose. The shapes the design reaches me through: `clarify-understood`, `clarify-explain` and `clarify-items`.

What exists, in `code/` and the vault, is evidence. Never the frame.

## The questions, in order

1. What is my purpose, in my words? Quote the line I stated it in.
2. Does the round open with it? My purpose heads the round, before any item.
3. Which of my words are examples? An example stays an example.
4. What exists that the design would inherit? Name it. The design keeps it only if my purpose asks for it.
5. Does each item trace to the purpose? Each names the words of mine it serves.
6. Does a rule need an exception? [[the-thinking-axioms|The Thinking Axioms]] rule it, under "A rule that needs an exception".

## The lessons

- A purpose I restate is the frame from then on.
- A skill family's purpose heads every round, whole.
- Too restrictive is a miss of its own. A likeness I give is never a spec.
- A say-back draws my corrections and additions before any design.
