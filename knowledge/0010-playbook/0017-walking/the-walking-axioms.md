# The Walking Axioms

Up: [[walking-MOC|Walking]]

What every walk respects, whatever it walks: an area's section, a subject, or one thing.

## 1. Features first, looks apart

A features walk checks what a screen does: each journey's flow and its edge cases, its other roles' views, and its docs pages, walked as their text.

Languages and widths are looks, a walk of their own.

A journey passes whole before the next. A check shared by journeys is walked once, in its first.

A feature walks its subject's life stage by stage, each stage in every place showing it, as [[protocol-my-walk|My Walk]] rules. There, a journey opening a stage passes whole. Another place's journey splits: each step walks at the stage it shows.

## 2. A fix walks the whole journey again

An issue is fixed, then the whole journey it sits in walks again. Nobody guesses which checks a fix reached.

## 3. A finding loops by which side is right

The code, the walk files and the docs page can disagree. Any of them can be wrong, or none can be right.

The analyzer states each side, with its line. I say which is right. A fixer brings the others in line.

A page describing what nobody built is a Not built piece. I rule: it is built now, or the page drops it.

## 4. One judge, one brain

The walker does, and judges nothing. The analyzer is the only judge. The lead reads the case, and decides with me. The reader brings me each docs page the tester passed, and judges nothing: I read every word myself.

I see one issue at a time. Sessions read ahead.
