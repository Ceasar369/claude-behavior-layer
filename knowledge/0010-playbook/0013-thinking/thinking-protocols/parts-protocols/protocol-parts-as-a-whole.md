# Protocol — Parts as a Whole

Up: [[parts-protocols-MOC|Parts Protocols]]

When the subject is running parts: a backend, a frontend, or both, thought through as a whole.

## The parts it touches

The running parts the subject names, and the vault folder each carries. [[the-parts|The Parts]] names them.

A decision that belongs to another part is named once, in the turn it is found, and again in the report. It opens no item.

## The questions, in order

1. What stands? Walk every screen with the Playwright MCP, and list every route, backend and frontend. A screen that fails is a candidate.
2. What kind of product is it? Its kind is ruled with me, and question 6's concepts follow from it.
3. What is the position on the whole? What each part does, and the path it beats. The first round tests it.
4. How does one request travel? A backend: whom it speaks for, what it checks, what it returns. A frontend: which zone guards a screen, what it reads before drawing, what follows an act.
5. Which loose ends did earlier slices leave in it? Each is a candidate.
6. Which standard concepts does its kind respect? Each is one item: where the part stands, from the code and the walk, and what it holds. A captured reference grounds each.
7. What does it keep, and what does it read from another layer? Nothing is kept against its folder's rule.

## The lessons

- A concept a provider may bring is recorded as a concept. Its build is named open.
- A rule every door shares changes in this part alone. The report names the other doors, with the line their shared document would take.
- A piece another layer holds is read from there. When the part may not call that layer, its owner pushes it, as The Sandbox rules.
- A standard the part cannot follow becomes an item. The item names what stops it.
- A concept that only guards live stays open until live exists.
- A moved address keeps answering until every part loading it has moved.
- A pushed copy holds only what its trigger sends. Name the trigger first, and each reader in another layer.
- A path no laptop can run is proven in halves, against stand-ins.
- A concept left unbuilt names the shared line it will need.
- Test the position's Wrong if against every ruled line.
- A copied design brings every field and every claim. Name each field it drops, and each claim nobody ruled.
- A part with no vault folder rules its home in round one.
- With no capture, a reference is read live and marked read live.
- Question 1's walk counts each screen's requests.
- A site with no requests reads question 4 as a reader's path: where they land, and where each page sends them.
- A new public page lists the vault lines it will state. Each leaves the vault.
- A concept every reference carries is named open, never rejected.
- A standard with a law behind it stays open for me and counsel. It is never a settled rule.
