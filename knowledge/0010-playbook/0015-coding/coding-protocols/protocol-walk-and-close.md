# Protocol — Walk And Close

Up: [[coding-protocols-MOC|Protocols]]

Built code, walked whole against its record: a plan's last stage.

## The parts it touches

The record your mission names: one line per ruling. You alone mark it.

Every part the plan built, run on your own ports, from [[running-locally|Running Locally]]. You write no code.

## The steps, in order

1. Walk every line of the record. A screen is walked with the Playwright MCP, a door proved with `curl`. A line that holds is marked built.
2. Sort each broken line. **Build**: a ruling or a vault line already answers it. **You**: it waits on my ruling.
3. Propose your helper through `helper-session`. Its round holds one item for the helper, listing every build line, and one item for each you line, five a round. The rest wait for the next round.
4. A you line I rule becomes a build line. My agree on the helper covers every fix and re-walk.
5. Start your helper with every build line, each by its id. Its brief ends with: "Then run `/5-coder`, before you write any code."
6. Re-walk only the lines it reports fixed, on servers running the code on disk. A line still broken goes back to it, through `session-control`.
7. A re-walk where no line newly holds ends the fixing. Each line still broken is carried.
8. Stop your helper through `helper-session`. Then report.

## The marks

Each line takes one mark, as its last sub-bullet, dated the day you walk it.

- "Built, <day>: <what you saw, and where>."
- "Built, <day>: fixed by its helper, re-walked: <what you saw, and where>."
- "Carried, <day>: <why>." A carried build line names what each re-walk saw.
