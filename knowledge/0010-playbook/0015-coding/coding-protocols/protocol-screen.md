# Protocol — Screen

Up: [[coding-protocols-MOC|Protocols]]

Screen code, in any frontend: a route a person sees, or a docs page.

## The parts it touches

A frontend's routes, parts and base, as [[the-layout|The Layout]] places them. Its words, in each language it carries.

[[the-screen-MOC|The Screen]], what sits inside a screen.

## The steps, in order

1. Build the look that The Look and The Screen rule. A mission naming a locked prototype winner builds that file.
2. Take each word a person reads from my ruling. A word nobody ruled is a marked stand-in, as `thinking.md` rules.
3. Run it on your own ports, from [[running-locally|Running Locally]].
4. While building, run only the test files you changed, as [[the-coding-axioms|The Coding Axioms]] rule. Check each changed screen at 1500 wide, in English, with no screenshot.
5. At the end, pass the gate once, under `taskpolicy -b`: `pnpm typecheck`, `pnpm lint` and `pnpm build`.
6. Then walk every changed screen once with the Playwright MCP, through your own frontend port: in each language it carries, at the four widths. Take a screenshot of each state. [[the-tools|The Tools]] holds the walk's traps.
7. A built winner's prototype leaves, by `prototype-remove`. The prototypes app still builds.

## The lessons

- A part two frontends hold is copied whole, byte for byte. A copy that drifts is recopied from its source.
- A ruled word is exact wherever it shows: its final period stays, and a docs page quotes the screen as the code holds it.
- A build proposes each new screen's words first: its opening line, hints, press lines and empty words. I rule them in its first round, and its walk finds each one on screen.
- The four widths are 1500, 1024, 900 and 390. Each screen then meets its kind's width standard.
- A build adding a form adds its fill, in the same change. Its walk fills that form with one press, before its act.
- The walk holds each list and record to its standards. A build breaking a rule of The Look or The Screen names it in its report.
